# STAR 回答模板

> 行為面試題（「請舉一個你⋯⋯的例子」）用 STAR 架構回答，讓答案具體、有條理、有結果。

---

## STAR 是什麼

| 字母 | 內容 | 占比 | 重點 |
|---|---|---|---|
| **S**ituation 情境 | 背景：在哪裡、什麼時候、遇到什麼狀況 | 15% | 簡短，一兩句就好 |
| **T**ask 任務 | 你的角色和要達成的目標 | 10% | 說清楚**你**負責什麼 |
| **A**ction 行動 | 你**具體**做了什麼、為什麼這樣做 | **50%** | 重點在這裡；用「我」而不是「我們」 |
| **R**esult 結果 | 成果，最好有**數字**；學到什麼 | 25% | 量化：不良率、時間、成本 |

### 品質工程師版本的加分技巧

- **Action 裡帶出品質手法**：「我先用**柏拉圖**找出主要不良，再用**魚骨圖**分析⋯⋯」
- **Result 一定要有數字**：「不良率從 6% 降到 1.6%」比「改善很多」有說服力
- **補一句標準化**：「之後我把這個做法寫進 SOP」，展現 PDCA 的 A

> ⚠️ **誠實原則**：[8D 模擬案例](../cases/8D-外殼卡扣毛邊客訴.md) 是虛構的練習，**不能**當成自己的工作經驗講。面試時可以說「我自己做過一個模擬案例練習 8D」，或用下面範例 1 的方式介紹這個學習專案。

---

## 範例 1：介紹這個學習專案

> **問題：「你沒有品質相關的工作經驗，怎麼證明你能勝任？」**

| | 回答 |
|---|---|
| **S** | 我在準備轉職品質工程師時，發現 SPC、MSA、抽樣這些工具，只看書很容易停留在背定義。 |
| **T** | 我給自己的目標是：不只要懂觀念，還要能**算**、能**解讀**，並且整理成可以分享的紀錄。 |
| **A** | 我建立了一個 GitHub 專案，依「品質基礎 → QC 七大手法 → SPC、MSA、抽樣 → 8D、FMEA → 品質系統」的順序學習，每個主題都整理筆記和手算範例。另外我用 Python 實作了三個工具：X̄-R 管制圖加上 8 條判異規則與 Cpk 計算、GR&R 分析，以及 AQL 查表和 OC 曲線，並用手算結果寫測試驗證程式的正確性。 |
| **R** | 實作過程讓我理解了很多只看書不會注意的地方。例如我模擬刀具磨損的數據時發現，管制圖比「只看規格」**早 3 組**就發出警訊；做 GR&R 時也發現，EV 大不一定是量具的問題，要搭配 R 圖看是不是某一位量測人員的手法不穩定。這些經驗讓我更能在實務上正確解讀數據。 |

## 範例 2：用數據解決問題（填入你自己的經驗）

> **問題：「請舉一個你用數據解決問題的例子。」**
>
> 經驗可以來自：工作、實習、學校專題、社團活動、打工。重點是「**用數據找原因、驗證對策**」的過程。

| | 我的回答 |
|---|---|
| **S** | （背景：在哪裡、遇到什麼問題？問題有多嚴重？） |
| **T** | （我的角色、目標是什麼？） |
| **A** | （我收集了什麼數據？用什麼方法分析？怎麼找到原因？怎麼驗證？做了什麼對策？） |
| **R** | （結果數字：從＿＿改善到＿＿；之後怎麼標準化？學到什麼？） |

## 常見行為面試題

每一題準備一個 STAR 故事。同一個故事可以從不同角度回答多題。

| 題目 | 想考察的能力 | 我的故事 |
|---|---|---|
| 舉一個你用數據解決問題的例子 | 分析能力、品質手法 | |
| 舉一個你和別人意見不合，最後怎麼解決的例子 | 溝通、說服力（品保常要說服產線） | |
| 舉一個你在壓力下完成任務的例子 | 抗壓性（客訴常有時間壓力） | |
| 舉一個你犯錯的例子，你怎麼處理？ | 誠實、從錯誤中學習 | |
| 舉一個你主動發現問題並改善的例子 | 主動性、持續改善 | |
| 舉一個你需要跨部門合作的例子 | 團隊合作（8D 需要跨部門） | |
| 如果產線主管不配合你的改善要求，你會怎麼做？ | 溝通、用數據說服 | |

### 「產線不配合」的回答方向

> 先了解對方不配合的原因（產能壓力？覺得沒必要？），再用**數據**說明問題的影響（例如不良造成的重工成本、客訴風險），並提出對產線**負擔最小**的做法。必要時請主管協調，但不是一開始就往上報。品保和產線的目標其實一致：都希望一次就做對。
