# 06 8D 問題解決

> 階段 4｜目標：能完整說明 D0～D8，分得清「圍堵」、「根本原因對策」、「預防再發」，並能找出**發生原因**與**流出原因**。

---

## 1. 8D 是什麼

### 是什麼

8D（Eight Disciplines）是福特汽車在 1987 年推行的**團隊式問題解決方法**，現在是**客訴處理的標準格式**。客戶要求供應商「回 8D」，就是要一份照這個架構寫的問題分析與改善報告。

### 什麼時候用

| 適用 | 不一定需要 |
|---|---|
| 客戶抱怨、退貨 | 原因明確、一個人就能解決的小問題 |
| 重大或重複發生的內部異常 | 單純的作業疏失，且已有標準作業 |
| 原因不明、需要跨部門合作 | |
| 客戶或品質系統要求 | |

### 和 PDCA 的對應

| PDCA | 8D |
|---|---|
| Plan | D1 成立團隊、D2 描述問題、D3 圍堵、D4 找根本原因、D5 選擇對策 |
| Do | D6 執行永久對策 |
| Check | D6 確認效果 |
| Act | D7 預防再發生、D8 恭賀團隊 |

---

## 2. D0 ～ D8 總覽

| 步驟 | 名稱 | 一句話 | 常見時限（依客戶而定） |
|---|---|---|---|
| D0 | 準備與緊急應變 | 判斷是否需要 8D，先做緊急處置 | 立即 |
| D1 | 成立團隊 | 找對的人 | 24 小時內 |
| D2 | 描述問題 | 把問題講清楚 | 24 小時內 |
| **D3** | **暫時圍堵** | **先止血，不讓不良品流到客戶** | **24 小時內** |
| **D4** | **找出根本原因** | **為什麼發生？為什麼沒被抓到？** | 7 天內 |
| D5 | 選擇並驗證永久對策 | 對症下藥，並證明有效 | 7～14 天 |
| D6 | 執行永久對策並確認效果 | 落實對策，用數據證明 | 30 天內 |
| **D7** | **預防再發生** | **標準化、水平展開** | 30～60 天 |
| D8 | 恭賀團隊 | 結案、分享經驗 | 結案時 |

> **面試重點是 D3、D4、D7**：先圍堵、再找根因、最後防止再發生。

## 3. 各步驟重點

### D0 準備與緊急應變（ERA）

- 判斷問題的嚴重性：是否涉及**安全或法規**？影響範圍多大？
- 必要時立即採取緊急應變措施（Emergency Response Action），例如通知客戶、暫停出貨

### D1 成立團隊

| 角色 | 職責 |
|---|---|
| 領導者 | 通常由品質工程師擔任，負責推動進度 |
| 成員 | **跨部門**：品保、製造、製程工程、設備、採購（若涉及供應商） |
| 推動者（高階主管） | 提供資源、排除障礙 |

> 團隊成員要**了解產品與製程**，並有權限執行對策。

### D2 描述問題

用 **5W2H** 把問題**量化、具體化**：

| 項目 | 問題 | 範例 |
|---|---|---|
| What | 什麼問題？ | 外殼卡扣處毛邊，導致組裝卡不上 |
| Who | 誰發現的？ | 客戶 A 公司組裝線 |
| Where | 在哪裡發現？哪個位置？ | 客戶組裝站；外殼內側第 3 號卡扣 |
| When | 何時發現？哪一批？ | 2026/10/05；批號 L261001 |
| Why | 為什麼是問題？ | 違反圖面「分模線毛邊 ≤ 0.05 mm」規定 |
| How | 怎麼發現的？ | 組裝時卡扣無法扣合 |
| How many | 多少？ | 抽 500 件有 21 件（4.2%） |

**IS / IS NOT 分析**（是／不是）：比較「有問題」和「沒問題」的差異，縮小原因範圍。

| | IS（是） | IS NOT（不是，但可能是） | 差異點 → 線索 |
|---|---|---|---|
| 什麼產品 | 外殼 X100 | 同模具的其他產品 | |
| 什麼缺點 | 毛邊 | 縮水、刮傷 | 毛邊和鎖模力有關 |
| 哪台機台 | B 機 | A 機 | **B 機有問題** |
| 什麼時間 | 9/20 之後生產的批 | 9/20 之前 | **9/20 前後 B 機有什麼改變？** |
| 哪個位置 | 第 3 號卡扣 | 其他卡扣 | 第 3 號卡扣位於分模面邊緣 |

> **好的問題描述，就已經解決一半的問題。** IS / IS NOT 的「差異點」常常直接指向原因。

### D3 暫時圍堵措施（ICA）

目的是**保護客戶**，不讓不良品繼續流出。**圍堵不是解決問題**，只是先止血。

**圍堵範圍**（要全部涵蓋）：

```
供應商來料 → 在製品 → 成品庫存 → 運送途中 → 客戶端庫存 → 客戶產線
```

| 動作 | 說明 |
|---|---|
| 追溯 | 用批號追溯所有可疑批的位置與數量 |
| 隔離 | 可疑品標示、隔離，暫停出貨 |
| 篩選 | 全檢挑選（必要時派人到客戶端挑選） |
| 加嚴檢驗 | 出貨前加嚴檢驗，直到永久對策有效 |
| 標示良品 | 篩選後的良品做**特殊標示**，讓客戶能辨識（例如貼綠色標籤） |
| 定義 Clean Point | 從哪一批開始確定是良品 |

> 圍堵措施要**驗證有效**：例如篩選後的批，客戶端不再發現不良。

### D4 找出根本原因

**最關鍵的步驟。** 要找出兩種原因：

| 原因 | 問的問題 | 範例 |
|---|---|---|
| **發生原因**（Occurrence） | 為什麼會**產生**不良？ | B 機油封磨損 → 鎖模力不足 → 毛邊 |
| **流出原因**（Escape / Detection） | 為什麼**沒被抓到**，流到客戶端？ | OQC 檢驗規範沒有定義卡扣處毛邊的檢查方法 |

> **只找發生原因是最常見的錯誤。** 客戶一定會問：「你們的檢驗為什麼沒抓到？」

再往下一層，有時還要找**系統原因**（為什麼管理系統允許這個問題存在？例如保養計畫的制定流程有缺陷）。

**常用工具**：

| 工具 | 用途 |
|---|---|
| IS / IS NOT | 縮小範圍 |
| 魚骨圖 | 列出可能原因（4M1E） |
| 5Why | 從表面原因追到根本原因 |
| 數據分析 | 層別法、散佈圖、管制圖 |
| 實驗 | DOE、比對試驗 |

**根本原因的驗證**：一定要證明，不能只靠推論。

> **開關驗證**：把原因「**放回去**」，問題會重現；把原因「**拿掉**」，問題會消失。能做到這一點，才算真正找到根本原因。

### D5 選擇並驗證永久對策（PCA）

- 對策要**直接對應**D4 找到的根本原因（發生 + 流出各自都要有對策）
- 實施前先**小規模驗證**，確認對策有效且**沒有副作用**
- 考慮對策的**強度**：防呆 > 自動檢測 > 修改 SOP > 教育訓練

| 對策強度 | 例子 | 效果 |
|---|---|---|
| 最強：消除原因 | 設計變更，讓問題不可能發生 | 一勞永逸 |
| 強：防呆（Poka-Yoke） | 治具讓零件裝反就放不進去 | 不依賴人 |
| 中：自動偵測 | 感測器監控鎖模力，異常自動停機 | 能及時發現 |
| 弱：修改 SOP、加強檢驗 | 增加檢驗項目 | 依賴人執行 |
| 最弱：教育訓練、宣導 | 「請作業員注意」 | **客戶通常不接受只有這一項** |

### D6 執行永久對策並確認效果

- 正式導入對策，並**移除 D3 的暫時圍堵措施**（確認永久對策有效後）
- 用**數據**證明效果：例如改善前不良率 4.2%，改善後連續 3 個月 0%
- 常見確認方式：連續 N 批無不良、Cpk 提升、客戶端無再發生

### D7 預防再發生

把這次的經驗**制度化**，避免同樣或類似的問題在其他地方發生：

| 動作 | 說明 |
|---|---|
| 標準化 | 修訂 SOP、檢驗規範、保養計畫 |
| 更新文件 | 更新 **PFMEA**、**管制計畫**（Control Plan） |
| **水平展開** | 同樣的對策套用到**類似的機台、產品、產線、廠區** |
| 經驗分享 | 建立 Lessons Learned 資料庫，作為新產品開發的參考 |

> D6 和 D7 的差別：D6 解決**這一個**問題，D7 防止**同類型**問題在別處發生。

### D8 恭賀團隊

- 肯定團隊成員的貢獻
- 確認所有文件完成、客戶同意結案
- 歸檔 8D 報告

## 4. 常見錯誤

| 錯誤 | 問題在哪 | 正確做法 |
|---|---|---|
| 根本原因寫「作業員疏忽」 | 沒有往下追，客戶不會接受 | 追問「為什麼制度允許疏忽發生？」，例如缺少防呆 |
| 對策只有「加強教育訓練」 | 對策強度最弱，人會忘記 | 搭配防呆、自動偵測等系統性對策 |
| 只找發生原因，沒找流出原因 | 檢驗漏洞還在，下次還會流出 | 發生與流出各自找原因、各自有對策 |
| 把圍堵當成永久對策 | 全檢挑選只是止血，成本高且無法持久 | 圍堵是 D3，根本原因對策是 D5 |
| 根本原因沒有驗證 | 對策可能做錯方向 | 用開關驗證、數據或實驗證明 |
| 沒有水平展開 | 其他機台或產品還有一樣的問題 | D7 檢查類似的地方 |
| 問題描述不具體 | 「品質不好」無法分析 | 用 5W2H 量化 |

## 5. 和其他問題解決方法的比較

| 方法 | 特色 | 常見用途 |
|---|---|---|
| **8D** | 強調**圍堵**與**團隊**，格式固定 | 客訴、重大異常 |
| PDCA | 最基本的改善循環 | 各種改善 |
| DMAIC（六標準差） | 強調**統計分析**，用於降低變異 | 改善專案 |
| A3 報告（豐田） | 一張 A3 紙呈現問題與對策 | 精實生產 |
| CAPA | 矯正與預防措施，ISO 與醫療器材常用的稱呼 | 品質系統要求 |

## 面試怎麼問 & 參考回答

**Q1：客戶抱怨一批產品不良，你第一步做什麼？**

> 第一步是圍堵，避免不良品繼續流到客戶端。先確認問題的內容和範圍，用批號追溯所有可疑品，包含在製品、庫存、運送途中和客戶端的庫存，全部隔離並篩選，篩選後的良品做特殊標示。同時成立跨部門團隊，24 小時內回覆客戶圍堵措施。圍堵完成後，再進行根本原因分析和永久對策。

**Q2：請說明 8D 的步驟。**

> D0 準備與緊急應變；D1 成立跨部門團隊；D2 用 5W2H 把問題描述清楚；D3 暫時圍堵，避免不良流出；D4 找出根本原因，包含發生原因和流出原因；D5 選擇並驗證永久對策；D6 執行對策並用數據確認效果；D7 預防再發生，包含標準化和水平展開；D8 恭賀團隊並結案。

**Q3：什麼是發生原因和流出原因？**

> 發生原因是為什麼會產生不良，例如設備參數異常；流出原因是為什麼檢驗沒有抓到，讓不良品流到客戶端，例如檢驗規範沒有涵蓋這個項目。兩者都要找，也都要有對策，否則即使製程改善了，檢驗漏洞還在，下次有其他問題時還是會流出。

**Q4：怎麼確認找到的是真正的根本原因？**

> 用開關驗證：把原因放回去，問題會重現；把原因拿掉，問題就消失。另外也可以用數據驗證，例如改善前後的不良率比較、相關性分析或實驗。只靠推論的原因，對策很可能做錯方向。

**Q5：根本原因是作業員疏忽，對策是加強教育訓練，這樣可以嗎？**

> 通常不行。作業員疏忽是表面原因，要繼續追問為什麼制度允許疏忽發生，例如缺少防呆、SOP 不清楚或作業設計容易出錯。教育訓練是最弱的對策，因為人會忘記、也會換人。應該優先考慮防呆或自動偵測這種不依賴人的對策，教育訓練可以作為輔助。

**Q6：D6 和 D7 有什麼不同？**

> D6 是針對這一次的問題，執行永久對策並確認效果；D7 是把經驗制度化，防止同類型的問題在其他地方發生，例如修訂 SOP、更新 PFMEA 和管制計畫，並水平展開到類似的機台、產品或產線。
